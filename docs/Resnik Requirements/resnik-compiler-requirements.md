## Functional Requirements 

[resnik-fn-0010] - The Resnik compiler shall contain a parser, lexer, and code generator.

[resnik-fn-0015] - The Resnik compiler shall only process HAL/S source code files with the *.hs or *.hal extension. 

### Lexer Functional Requirements 

[resnik-lex-0010] - The Resnik lexer shall be written in Python rply, a Python Lex/Yacc framework library.

[resnik-lex-0015] - The Resnik lexer shall comply with the case insensitivity of the HAL/S format standard.

[resnik-lex-0030] - The Resnik lexer shall identify and discard full-line comments (column-sensitive) comments that are defined as the first non-blank character of a line with the letter "C" (case-sensitive, typically uppercase). The shall treat the entire line as a comment and will discard the everything after "C". Here is an example, "C This is a full-line comment"

[resnik-lex-0035] - The Resnik lexer shall identify and discard embedded inline block comments with the syntax:  /* ... */. Block comments can appear anywhere that whitespace is allowed and span multiple lines. Everything after "/*" and before "*/" shall be ignored by the lexer.

[resnik-lex-0040] - The Resnik lexer shall identify and discard extra spaces, tabs, and newlines that don't affect logic of the inputted source code. 

[resnik-lex-0045] - The Resnik lexer shall recognize statement terminators that are defined as a semicolon ";" as the end of a logical statement, even if it spans multiple physical lines.

[resnik-lex-0050] - The Resnik lexer shall tokenize all HAL/S reserved words (keywords) (ex: PROGRAM, CLOSE, DECLARE, PROCEDURE, FUNCTION, DO) defined in the HAL/S Programming Language specification USA003088.

[resnik-lex-0055] - The Resnik lexer shall tokenize identifiers that are names for variables and labels. Identifiers must start with a letter (A-Z) and can include digits (0-9).

[resnik-lex-0060] - The Resnik lexer shall tokenize numerics that are integers and floating-point numbers (including scientific notation like 12.5E-3).

[resnik-lex-0065] - The Resnik lexer shall tokenize Bit/Hex Strings (ex: BIN '1010' or HEX 'FF').

[resnik-lex-0070] - The Resnik lexer shall tokenize character strings enclosed in single quotes.

[resnik-lex-0075] - The Resnik lexer shall tokenize arithmetic operators (+, -, *, /, **), Relational (=, <, >, <=, >=, ¬=), and Boolean (AND, OR, NOT).

[resnik-lex-0080] - The Resnik lexer shall handle HAL/S special notation (e.g. vector/matrix ops like A(*) or B(#,#)).

[resnik-lex-0085] - The Resnik lexer shall handle the "At" Symbol "@" that for addressing or specific hardware interfacing.

[resnik-lex-0090] - The Resnik lexer shall recognize the HAL/S "Three-Line Format" to represent math with "column 1" indicators that define the purpose of a line: M-line (Main): The standard statement line. S-line (Superscript): Used for exponents Sub-line (Subscript): Used for indices.

[resnik-lex-0095] - The Resnik lexer shall detect any characters outside the HAL/S character set (Standard ASCII plus specific NASA-defined symbols) and report it as an error to the user. 

[resnik-lex-0100] - The Resnik lexer shall detect detect incorrectly formatted bit strings (ex: BIN '102') and report it as an error to the user.

[resnik-lex-0105] - The Resnik lexer shall detect detect any string literal is not closed before the end of a source file and report it as an error to the user.

[resnik-lex-0110] - The Resnik lexer shall generate a "Stream of Token Objects" for the Resnik parser that contains: 1) Type: An integer or enum (e.g., KEYWORD_IF, IDENTIFIER). 2) Lexeme: The actual string (e.g., "count"). 3) Metadata: Line number, column number, and file source (crucial for error reporting). 

[resnik-lex-0110] - The Resnik lexer shall genrate a Intermediate Representation JSON file that contains the lexer's output. This file is used for debugging the performance of the lexer. 

### Parser Functional Requirements 

[resnik-parse-0010] - The Resnik parser shall be written in Python rply, a Python Lex/Yacc framework library.

[resnik-parse-0015] - The Resnik parser shall enforce HAL/S strong typing standard.

[resnik-parse-0020] - The Resnik parser shall use the "Stream of Token Objects" generated by the lexer as input.

[resnik-parse-0025] - The Resnik parser shall enforce the strict modular hierarchy required by the HAL/S language specification that includes the following nesting order: 1) Program/Compool Level: The highest level of organization, 2) Block Structure: Proper opening and closing of PROGRAM, PROCEDURE, TASK, and FUNCTION blocks, 3) Scoped Visibility: Ensuring that CLOSE statements match their corresponding opening labels.

[resnik-parse-0030] - The Resnik parser shall perform spatial reconstruction of the tokens generated by the lexer: 1) Exponentiation: Associate tokens from the S-line with their base variables on the M-line, 2) Subscripting: Associate tokens from the Sub-line with their array/matrix bases, 3) Matrix/Vector Recognition: Identify overbars (on the S-line) or underbars (on the Sub-line) to determine if a variable should be treated as a VECTOR or MATRIX type.

[resnik-parse-0035] - The Resnik parser shall process HAL/S DECLARE statements: 1) Attributes: Handle mandatory attributes like PRECISION (SINGLE/DOUBLE), TYPE (SCALAR, VECTOR, MATRIX, INTEGER, BIT, CHARACTER), and ACCESS (static vs. automatic), 2) Initialization: Parse the INITIAL or CONSTANT clauses to ensure values match the declared type, 3) Compool Integration: Parse INCLUDE or REPLACE directives to integrate external symbol definitions.

[resnik-parse-0040] - The Resnik parser shall build an Abstract Syntax Tree (AST) in the JSON format that respects HAL/S-specific precedence: 1) Standard Math: Order of operations for +, -, *, /. 2) Vector/Matrix Math: Handle specialized operations like the cross product (*) and dot product (.) which have different semantic meanings in HAL/S than in standard algebra. 3) Bitwise vs. Logical: Correctly distinguish between bit-string manipulations and boolean logic in IF statements.

[resnik-parse-0045] - The Resnik parser shall validate the syntax of real-time flight control structures: 1) Scheduling: Parse SCHEDULE, WAIT, TERMINATE, and CANCEL statements, including their time-frequency parameters (e.g., REPEAT EVERY, ON, PRIORITY) 2) Decision Logic: Validate the structure of IF...THEN...ELSE and the DO...END loops (including WHILE, UNTIL, and FOR iterations).

[resnik-parse-0050] - The Resnik parser shall perform semantic "sanity" checks: 1) Mismatched Dimensions: E.g., trying to add a VECTOR(3) to a SCALAR. 2) Illegal Branching: Jumping into the middle of a PROCEDURE or TASK block from outside.

### Backend (code generator) Functional Requirements

[resnik-backend-0010] - The Resnik backend shall translate the parsers AST file into Rust programming language source code.

[resnik-backend-0015] - The Resnik backend shall use the JSON AST file generated by the parser as input.

[resnik-backend-0020] - The Resnik backend shall translate HAL/S PROGRAM or TASK blocks into Rust mod or fn structures.

[resnik-backend-0025] - The Resnik backend shall map IF...THEN...ELSE conditional statement into Rust's if expressions, and convert DO...FOR loops into Rust for ... in ... iterators.

[resnik-backend-0030] - The Resnik backend shall convert HAL/S UPPER_CASE identifiers to Rust's snake_case or PascalCase to follow standard styling (rustfmt).

[resnik-backend-0035] - The Resnik backend shall ensure all variables are initialized before use to satisfy Rust's "non-null" and safety requirements.

[resnik-backend-0040] - The Resnik backend shall map HAL/S "Compools" (common data pools) to Rust static variables or protected Arc<Mutex<T>> structures if multithreading is involved.

[resnik-backend-0045] - The Resnik backend shall determine if a HAL/S variable is ever modified; if so, declare it as let mut in Rust; otherwise, default to immutable let.

[resnik-backend-0050] - The Resnik backend shall map HAL/S real-time tasks to an asynchronous runtime like Tokio or an RTOS (Real-Time Operating System) wrapper.

[resnik-backend-0055] - The Resnik backend shall translate HAL/S PRIORITY levels into thread or task priority settings in the target environment.

[resnik-backend-0060] - The Resnik backend shall include a "Runtime Support" library in the generated Rust project that provides these mathematical and aerospace intrinsics (ex: ABVAL for absolute value, UNIT for unit vectors).

[resnik-backend-0065] - The Resnik backend shall translate HAL/S runtime errors (ON ERROR) into Rust's Result<T, E> or panic! mechanisms

[resnik-backend-0070] - The Resnik backend shall perform "Dead Code Detection" and warn the user if HAL/S code is unreachable.

[resnik-backend-0075] - The Resnik backend shall review the AST for HAL/S unit data (meters, seconds) and ensure the generated Rust math doesn't violate these dimensions by using uom crate.

[resnik-backend-0080] - The Resnik backend shall provide "Rust-like" errors if the HAL/S source code will result in a borrow-checker violation (e.g., two tasks trying to write to the same COMPOOL variable simultaneously without a lock), the backend should flag this as a Concurrency Error during the generation phase.

[resnik-backend-0085] - The Resnik backend shall map the HAL/S "**" operator for matrices or native vector cross-products into Rust crate-specific methods (e.g., vector_a.dot(&vector_b) or matrix.pow(n)).

[resnik-backend-0090] - The Resnik backend shall translate HAL/S subscripts into Rust's range syntax: variable[start..end].

[resnik-backend-0095] - The Resnik backend shall determine HAL/S variables scope into Rust's scope. Because HAL/S COMPOOL (Common Data Pools) are essentially global, the backend should wrap these in a lazy_static! or a thread-safe Arc<Mutex<T>> if the HAL/S tasks are concurrent.

[resnik-backend-0100] - The Resnik backend shall perform a pass of the AST to determine if a variable is ever assigned; if not, it the variable be generated as a standard immutable let.

[resnik-backend-0105] - The Resnik backend shall use Rust’s newtype pattern to represent HAL/S specific types (like BIT strings or ANGULAR types) to ensure that math on degrees and math on radians aren't accidentally mixed at compile time.

## Non-Functional Requirements

[resnik-nonfn-0010] - The Resnik compiler shall comply with the HAL/S Programming Language specification USA003088
32.0/17.0.

[resnik-nonfn-0015] - The Resnik compiler shall support the following hardware platforms: 1)x86, 2) ARM Cortex.

[resnik-nonfn-0020] - The Resnik compiler shall support the following Operating Systems: 1) Linux, 2) MacOS, 3) Windows Command-Line Interpreter.

[resnik-nonfn-0025] - The Resnik backend shall not just produce "Rust-flavored HAL/S". it shall produce code that passes Rust’s strict compiler checks.

[resnik-nonfn-0030] - The Resnik lexer, parser and backend shall report the line number and identifiy the erroneous source code to the user when detecting a coding error in the inputted file.
